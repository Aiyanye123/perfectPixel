# PerfectPixel Next：像素画逆向重建算法提案

> 状态：研究与实现路线草案  
> 目标：降低算法对原图质量的要求，并让失败可检测、结果可比较、过程可人工修正。

## 当前实现状态

第一版多候选经典后端已实现，当前包含：

- FFT 与梯度检测结果的基础、二分之一、二倍和邻近尺寸候选；
- 常见尺寸候选；
- 边界对齐、内部边缘和网格间距规则度快速评分；
- 最近邻与轻微方框模糊重渲染评分；
- 防止密网格过拟合的网格复杂度惩罚；
- 面向前景与边缘的细节保留评分，避免纯色背景掩盖主体细节损失；
- Top-3 候选与初始置信度输出。

边界感知颜色采样也已实现为 `adaptive` 模式：通过格内空间权重降低边缘混色影响，并使用鲁棒颜色
残差迭代抑制异常颜色。该模式仍然逐格独立工作，尚未使用共享调色板或相邻格联合标注。

网格微调已改为固定数量边界：微调只能移动内部边界，不能增加或删除格子。手动指定 `313×313`
或自动选择某个候选后，最终输出会严格保持该尺寸，避免正方形输入因独立线吸附变成矩形结果。

当前置信度属于相对启发式指标，尚未经过基准数据校准。PatchMatch、联合调色板、非刚性网格与
学习模型仍属于后续研究方向。

## 1. 结论摘要

当前算法适合处理“轴对齐、全局规则、像素格近似正方形、边缘清晰”的图片，但真实 AI
像素风图片通常同时包含非整数缩放、局部扭曲、抗锯齿、渐变、纹理、压缩噪声和不稳定调色板。
继续增加 FFT 或 Sobel 参数只能扩大适用范围，无法消除算法模型与真实输入之间的差距。

建议将下一代算法定义为一个**带先验约束的逆渲染问题**：

```text
输入的高分辨率像素风图片
    ≈
理想低分辨率像素画
    + 网格几何变形
    + 非整数缩放 / 重采样
    + 模糊 / 抗锯齿
    + 压缩与颜色噪声
```

算法不再一次性猜出唯一网格，而是：

1. 生成多个合理网格候选；
2. 对每个候选联合恢复网格几何、像素颜色和调色板；
3. 将恢复结果重新渲染到输入尺寸；
4. 根据“重新渲染后能否解释原图”进行评分与排序；
5. 输出最佳结果、备选结果和置信度。

推荐按三个阶段实现：

- **阶段 A：多候选 + 全局评分**，低风险，优先解决尺寸误判和静默失败；
- **阶段 B：联合优化逆渲染**，解决局部形变、抗锯齿和颜色污染；
- **阶段 C：可选学习模型**，使用合成退化数据提升困难图片表现。

## 2. 当前实现的核心假设

当前 OpenCV 与 NumPy 后端共享同一算法结构：

1. 对灰度图执行 FFT，并从水平、垂直投影中寻找周期峰值；
2. FFT 结果不可信时，使用 Sobel 梯度峰值间距估算网格尺寸；
3. 从图像中心向外生成等间距网格线；
4. 每条网格线在局部范围内独立吸附到最强梯度峰；
5. 对每个格子执行中心、中位数或双聚类主色采样。

这个设计隐含了以下假设：

- 网格是水平和垂直的；
- 整张图只有一个固定周期；
- 水平与垂直像素格尺寸近似相同；
- 网格形变可通过独立移动整条水平线或垂直线修复；
- 每个格子的正确颜色能直接从该格内部统计得到；
- 最强边缘通常就是网格边界；
- 单次检测结果足够可信，不需要候选比较和置信度。

这些假设对规则素材有效，但对 AI 生成图并不稳定。

## 3. 已观察到的失败模式

### 3.1 单一周期容易选中谐波

真实目标可能是 `24×24`，但 FFT 或梯度可能选中其两倍、三倍或局部纹理周期，得到
`48×48`、`72×72` 等结果。当前算法只保留一个峰值，无法比较“基础周期”和“谐波周期”。

### 3.2 局部线条会干扰全局网格

角色轮廓、眼睛、衣物纹理等高对比边缘可能比像素格边界更强。当前网格线在局部搜索窗口内选择
最强梯度，因此容易吸附到主体轮廓，而不是规则网格位置。

### 3.3 网格微调缺少整体约束

每条线独立移动，没有显式约束相邻线不能交叉或重叠、格子间距变化必须平滑、线条数量保持不变，
以及水平线与垂直线接近正交。

仓库样例中可观察到：

| 图片 | 自动估计 | 最终输出 | 现象 |
| --- | ---: | ---: | --- |
| `girl.jpg` | `24×24` | `24×24` | 理想输入，表现正常 |
| `avatar.png` | `48×48` | `48×48` | 可能选中更细的周期 |
| `car.png` | `79×79` | `81×74` | 微调后尺寸明显漂移 |
| `pig.png` | 检测失败 | 检测失败 | 无可靠兜底 |
| `skull.png` | `126×126` | `127×123` | 近方形结果仍发生漂移 |

这些数字不能证明目标真实尺寸，但足以说明当前流程无法保证最终网格与初始假设一致，也没有可靠
置信度告诉用户结果是否可信。

### 3.4 单格采样无法逆转抗锯齿

中心采样容易命中错误颜色；中位数会压平细节；双聚类多数色可能把轮廓边缘归入背景。
三种方式都是逐格独立决策，没有利用共享调色板、邻接关系或重渲染误差。

### 3.5 固定阈值限制泛化能力

当前实现包含多项固定经验参数，例如 FFT 峰值相对阈值、最小峰距、梯度阈值、最大像素尺寸和
宽高比例阈值。这些值对不同生成模型、图片尺寸和后处理方式不一定成立。

## 4. 推荐总体架构：分析合成一体化

建议将核心状态表示为：

```text
Z = {
  grid_shape,        # 输出网格宽高
  grid_geometry,     # 全局变换与局部网格形变
  cell_colors,       # 每个格子的离散颜色
  palette,           # 共享调色板
  degradation,       # 缩放核、模糊、抗锯齿、噪声等
  foreground_mask    # 可选：主体 / 背景 / 透明区域
}
```

通过渲染器 `R(Z)` 将候选低分辨率结果重新生成到原图尺寸，并最小化：

```text
E(Z) =
  λ_photo   · 鲁棒颜色重建误差
+ λ_edge    · 边缘距离误差
+ λ_grid    · 网格规则性惩罚
+ λ_palette · 调色板复杂度惩罚
+ λ_label   · 相邻格颜色一致性先验
+ λ_model   · 退化模型复杂度惩罚
```

关键区别是：**输出结果必须能够解释输入图，而不是仅依赖某个检测器的单次判断。**

## 5. 阶段 A：多候选网格与全局评分

这是最推荐的第一步，不需要神经网络，也不需要立即重写全部算法。

### 5.1 多来源候选生成

同时生成候选，而非只保留一个答案：

- 2D FFT 峰值及其基础周期、二倍和三倍谐波；
- 2D 自相关或相位相关峰值；
- 水平、垂直梯度间距直方图；
- PatchMatch 或局部块相似性产生的重复位移；
- 常见像素画尺寸先验，例如 `16`、`24`、`32`、`48`、`64`、`96`；
- 用户指定尺寸附近的小范围候选。

每张图保留 Top-K，例如 10 到 30 个候选宽高。PatchMatch 类近规则纹理格点检测表明，局部补丁
对应关系可以帮助恢复存在畸变和缺失的重复结构，比单纯频谱峰值更能适应近规则纹理。

### 5.2 谐波消歧评分

针对每个候选尺寸，快速构建网格并计算：

- **格内一致性**：每个格内部颜色方差是否较低；
- **边界对齐度**：高梯度是否集中在格子边缘附近；
- **内部边缘惩罚**：高梯度是否大量出现在格子内部；
- **周期一致性**：不同区域估计出的周期是否相近；
- **网格规则度**：相邻间距变化是否平滑；
- **调色板压缩率**：是否能用较小调色板解释大部分格子；
- **重渲染误差**：快速最近邻重渲染后与输入是否接近。

最终输出最佳候选及 Top-3 备选，而不是静默选中一个结果。

### 5.3 置信度与拒绝机制

置信度至少应包含最佳候选与第二候选的分数差、不同检测器是否达成一致、网格规则度、重渲染误差，
以及自动检测在轻微裁剪和缩放扰动下是否稳定。

如果置信度低，应明确返回“无法可靠自动判断”，并展示三个候选供用户选择。可靠拒绝比错误但看似
确定的结果更有价值。

### 5.4 阶段 A 的预期收益

- 显著降低 `24×24` 与 `48×48` 等谐波误判；
- 避免单次 FFT 或梯度失败导致整个流程失败；
- 为 Web UI 提供候选结果、评分和置信度；
- 为后续逆渲染优化提供合理初始化。

## 6. 阶段 B：联合网格几何优化

### 6.1 从“独立网格线”改为“受约束网格”

建议采用从简单到复杂的几何模型：

1. **规则轴对齐网格**：平移、统一格宽和格高；
2. **仿射网格**：允许旋转、斜切和非等比缩放；
3. **单应性网格**：允许轻微透视；
4. **平滑非刚性网格**：允许局部弯曲和生成模型造成的形变。

非刚性网格可以使用稀疏控制点配合双线性、B-spline 或 Thin-Plate Spline 插值，但必须加入间距
平滑、正交性、弯曲能量、网格单调性、防折叠和面积变化限制。

文档去畸变研究中的网格正则化和 3D 网格方法说明，结构化网格比逐条独立线更适合描述局部形变。
PerfectPixel 不需要完整 3D 模型，但可以借鉴其“全局规则 + 局部形变”的参数化方式。

### 6.2 动态规划追踪网格边界

对于局部弯曲边界，可以让每条网格线成为一条路径，并通过动态规划寻找：

```text
路径成本 =
  - 边缘响应
  + 偏离理想位置惩罚
  + 路径弯曲惩罚
  + 与邻线间距变化惩罚
```

与当前整条线只选择一个坐标相比，这种方式能表达局部形变，同时保持线条平滑。

### 6.3 交替优化

推荐循环执行：

1. 固定网格，估计每格颜色；
2. 固定颜色，优化网格几何，使重渲染误差下降；
3. 固定二者，估计模糊和重采样参数；
4. 重复至收敛或达到迭代上限。

为了控制速度，可先在低分辨率代理图上粗优化，再在原图上精调。

## 7. 阶段 B：联合颜色与调色板恢复

### 7.1 边界感知的格内采样

每个格子的中心区域通常比边缘区域更可靠。可使用空间权重：中心权重高，靠近网格边缘权重低，
检测到抗锯齿或轮廓混色时进一步降权。再使用 Huber 损失、截尾均值或颜色混合模型，而不是直接
中心采样。

### 7.2 全局共享调色板

像素画通常使用有限调色板。建议：

1. 在感知颜色空间中聚类候选颜色；
2. 自动尝试多个调色板大小；
3. 根据重建误差与调色板复杂度选择平衡点；
4. 允许用户锁定、合并、替换颜色。

颜色差异评分推荐使用 CIELAB / CIEDE2000 或经过验证的感知颜色空间，而不是直接 RGB 欧氏距离。

### 7.3 图模型联合标注

将每个格子视为图节点，将调色板颜色视为标签：

```text
单点代价：该颜色重渲染后能否解释格内观测
邻接代价：相邻格是否应共享颜色
边缘保护：原图存在强轮廓时，降低邻接平滑约束
```

这类离散能量可使用 alpha-expansion / graph cuts 近似优化。它比逐格独立选择颜色更能消除孤立
噪点，同时保留真实轮廓。

### 7.4 前景和透明背景

可选增加前景掩码与 alpha 标签：识别纯色或近纯色背景，将边缘混色分解为前景颜色、背景颜色和
覆盖率，输出透明 PNG，避免背景污染轮廓颜色。

## 8. 阶段 B：退化模型与重渲染评分

### 8.1 需要模拟的常见退化

- 最近邻、双线性、双三次和未知混合缩放；
- 非整数缩放倍数；
- 高斯模糊和锐化；
- 抗锯齿；
- JPEG / WebP 压缩；
- 色彩偏移、轻微噪点和局部纹理；
- 裁剪偏移和不完整边缘格子；
- 局部几何扭曲。

### 8.2 可微与不可微实现

第一版无需完整可微渲染器。可对网格宽高、缩放核和调色板大小使用离散候选，对平移、仿射、
模糊强度和局部控制点使用交替搜索、坐标下降或粗到细优化。

后续如果引入 PyTorch，可使用自动微分优化连续几何和退化参数。可微渲染相关研究展示了通过
重渲染损失恢复隐藏结构的通用方法；本项目可采用更轻量的二维栅格版本。

### 8.3 为什么重渲染评分很重要

仅看输出像不像像素画会偏向过度简化。重渲染评分要求输出在经过合理退化后仍能解释输入，因此能
约束算法不要随意改变轮廓、不要为了减少颜色丢失重要细节，也不要选择只在频谱上合理但视觉错误的
网格尺寸。

## 9. 阶段 C：可选学习模型

经典优化应继续作为默认后端，因为它可解释、便携、容易人工干预。学习模型建议作为困难输入的
可选加速器或候选生成器，而不是直接生成最终像素画。

### 9.1 合成退化训练数据

可从真实干净像素画出发，随机应用非整数缩放、多种重采样核、局部位移场、透视、模糊、锐化、
压缩、渐变、光照、纹理污染和背景混合。这样可以得到准确的真实网格、颜色、几何和退化参数。

Real-ESRGAN 等盲图像恢复工作证明了高阶合成退化对覆盖真实复杂退化的重要性；本项目可借鉴这一
思想，但训练目标应是恢复离散网格与颜色，而非生成自然图像细节。

### 9.2 推荐预测目标

轻量模型可以预测：

- Top-K 网格尺寸概率；
- 网格交点或位移场；
- 每像素属于格子内部、格子边界或抗锯齿区域的概率；
- 背景 / 前景 / 透明度；
- 预测置信度。

模型输出仍交给逆渲染优化验证和精调。

### 9.3 不建议默认使用生成式扩散模型

生成式模型可能让结果“更好看”，但会产生原图不存在的像素细节，不适合追求忠实还原的默认流程。
如果未来增加“创意重绘”模式，应与“忠实恢复”模式明确分离。

## 10. 建议的产品交互

算法改进需要配合界面设计，才能让不确定性真正可用。

### 10.1 自动模式

- 输出最佳结果；
- 显示总体置信度；
- 显示检测尺寸、调色板大小和主要退化类型；
- 置信度低时明确提醒，而不是直接宣称成功。

### 10.2 候选比较

同时展示 Top-3：

```text
候选 A：32×32，置信度 0.82
候选 B：31×32，置信度 0.67
候选 C：64×64，置信度 0.58
```

### 10.3 人工修正

- 拖动少量网格控制点；
- 锁定输出宽高；
- 锁定或编辑调色板；
- 点击格子替换颜色；
- 查看每格置信度热力图；
- 将人工修正保存为后续评估数据。

## 11. 评估体系

没有评估数据时，算法很容易只对少数展示图优化。

### 11.1 合成基准

使用干净像素画生成带真实标注的退化输入，衡量：

- 网格尺寸准确率；
- 网格交点平均误差；
- 每格颜色准确率；
- CIEDE2000 调色板颜色误差；
- 轮廓 Edge F1；
- 重渲染误差；
- 置信度校准；
- 运行时间和峰值内存。

### 11.2 真实图片基准

建立失败类型分层的数据集：规则放大、非整数缩放、抗锯齿、压缩、局部扭曲、透视、渐变和光照、
纹理背景、非正方形格子和不完整裁剪。真实图片没有唯一真值时，使用人工标注尺寸、局部格点和
成对偏好评价。

### 11.3 必须包含失败检测指标

除准确率外，还应评估算法高置信度时有多可靠、低置信度拒绝后剩余结果质量提升多少，以及 Top-3
候选中是否包含正确答案。

---

## 12. 推荐实现顺序

### Milestone 0：评估基础设施

- 建立 `benchmarks/` 数据格式；
- 编写合成退化生成器；
- 固化当前算法基线；
- 记录每张图的候选尺寸、最终尺寸、耗时和失败原因。

这是所有算法改进的前置条件。

### Milestone 1：多候选经典后端

- 实现 FFT、自相关、梯度和常见尺寸多候选；
- 实现候选全局评分；
- 返回 Top-3 与置信度；
- 保持当前采样与 Web API 兼容。

预计这是投入产出比最高的一步。

### Milestone 2：规则网格逆渲染

- 实现快速重渲染器；
- 联合搜索网格尺寸、平移、格宽高、缩放核和模糊；
- 使用重渲染误差重新排序候选；
- 增加低置信度拒绝机制。

### Milestone 3：调色板联合优化

- 实现边界感知格内观测；
- 实现全局调色板；
- 实现基于图模型的颜色联合标注；
- 支持背景和透明度。

### Milestone 4：非刚性网格

- 从仿射和单应性开始；
- 再增加低自由度平滑控制点；
- 实现防折叠、间距和弯曲约束；
- 仅在规则模型无法解释输入时启用。

### Milestone 5：学习辅助

- 训练轻量候选生成和置信度模型；
- 模型输出必须经过经典优化验证；
- 保留完全离线、无模型依赖的经典后端。

## 13. 建议的代码边界

下一代算法不应继续复制 OpenCV 与 NumPy 两份完整逻辑。建议拆分为：

```text
src/perfect_pixel_next/
  candidates.py       # 多来源网格候选
  observations.py     # 梯度、颜色、边缘和局部统计
  geometry.py         # 规则、仿射、单应性、非刚性网格
  palette.py          # 调色板和图模型标注
  renderer.py         # 退化模拟与重新渲染
  scoring.py          # 候选能量与置信度
  optimizer.py        # 粗到细和交替优化
  diagnostics.py      # 可视化与失败解释
  api.py              # 稳定公共 API
```

OpenCV 与 NumPy 应作为底层算子能力差异，而不是两份独立算法。

建议新 API：

```python
result = reconstruct_pixel_art(
    image,
    mode="balanced",       # fast / balanced / quality
    grid_hint=None,
    palette_hint=None,
    allow_deformation=True,
    candidates=3,
)

result.best.image
result.best.grid
result.best.palette
result.best.score
result.confidence
result.alternatives
result.diagnostics
```

## 15. 最终建议

近期最值得实现的是：

```text
多来源 Top-K 网格候选
    + 全局规则度评分
    + 快速重渲染评分
    + 置信度与拒绝机制
```

这一组合不依赖大型模型，能直接兼容当前 Web 和便携版，并会为后续调色板优化、非刚性网格和学习
模型建立稳定基础。

不建议第一步就训练端到端生成模型。没有基准数据、置信度和重渲染验证时，模型即使生成了更漂亮的
结果，也难以判断它是在忠实恢复，还是在重新创作。
